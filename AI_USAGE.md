# AI Usage Report

## Tools Used

- **Claude Code (Claude Opus)** — used throughout the project for guidance, API surface explanations, code review, and generating specific components (listed below).

## Work Done Independently

Core application code was written independently. AI explained the relevant API surface (method names, parameters, imports, return types). Architecture decisions, dataset selection (HotpotQA for its multi-hop ground truth), stack selection, system prompt engineering, evaluation design, and debugging were completed independently.

### Guidance and Explanations (throughout)

- **Qdrant client** — `query_points` vs deprecated `search`, `collection_exists`, `VectorParams`, `Filter`/`FieldCondition` for payload filtering, payload indexes
- **Streamlit** — `st.session_state`, `st.form`, `st.spinner`, `st.sidebar`, `set_page_config` must be first call
- **RAG concepts** — embeddings, cosine similarity, BM25, Reciprocal Rank Fusion formula, dense vs sparse retrieval trade-offs
- **Evaluation metrics** — Recall@K, MRR, token-level F1, citation accuracy definitions

AI explanations were not taken at face value. API surface claims were cross-checked against official documentation (OpenAI docs, Qdrant docs, Streamlit docs).


### Code Written by AI

The following were generated by AI and reviewed:

- **tests_unit.py** — 31 unit tests covering pure functions (rrf, tokenize, build_context, recall_at_k, reciprocal_rank, chunk_text, token_f1, citation_accuracy, usage tracking). Each test was reviewed for correctness before inclusion.
- **ingest_fixed.py** — fixed-size chunking ingestion script. Same pattern as `ingest.py` but chunks each paragraph with `chunk_text(text, "fixed")` before embedding.
- **synthetic.py** — 8 synthetic contradictory documents for testing contradiction detection. The facts to contradict were chosen independently; the generated content was reviewed.
- **Docstrings** — docstrings for all public functions across retrieval.py, generate.py, and documents.py. Each was reviewed for accuracy.
- **README.md** — structure and content were drafted by AI, then reviewed and modified.

### Code Review

A code review was performed by Claude Code, producing 8 findings. After analysis:

- **4 real bugs fixed:** parallel tool calls not handled, variable shadowing, unhandled `finish_reason`, import-time side effects in tests
- **2 false positives:** usage tracking and None handling already existed in the code
- **2 disregarded:** not applicable to the project's usage pattern
